# VPN VPS: Xray, автопочинка v3.2

## Назначение и конфигурация
VLESS/XHTTP/TLS и VLESS/TCP/REALITY поддерживаются одним Xray.
Билдер заменяет только outbound tag=proxy в существующем конфиге (--base).
Inbounds, routing, DNS и остальные outbounds сохраняются. Установка с нуля
требует заранее подготовленного базового конфига. Индекс записи подписки
не является постоянным идентификатором ноды. Логи используют только номер
записи, транспорт и безопасный код ошибки, без значений подписки.

## Безопасная установка кандидата
update.sh запускается от root и удерживает flock весь запуск, включая паузы.
apply_candidate.sh вызывается только из update.sh под этой блокировкой.
Временный .json создаётся в каталоге рабочего конфига; владелец, группа и
режим копируются с рабочего файла. Доступ и xray run -test проверяются через
runuser от User= сервиса. После бэкапа выполняется атомарная замена, restart,
проверка active и OpenRouter. При ошибке после замены выполняется откат.
Код helper 2 останавливает перебор, в том числе при ошибке отката.
Бэкапы .backup.*.json содержат секреты; их нельзя публиковать. Ротации нет.

## Ограничения
- runuser не воспроизводит sandbox/capabilities systemd.
- SIGKILL и отключение питания не покрыты обработчиком отката.
- Блокировка защищает только обновлённый update.sh, не ручное редактирование.
- HTTP 200 OpenRouter не является полной проверкой всех сервисов.
- Уведомление в журнале означает попытку отправки, не доставку Telegram.
- ATTEMPTS=4, RETRY_DELAY=180; окно не фиксировано в 20 минут.
  При большом числе нод TimeoutStartSec=1800 может оказаться недостаточным.
  Бюджет времени и отмену systemd следует проверить отдельно перед боевым вводом.

## Воспроизводимые проверки
Из корня репозитория на Linux с bash, GNU coreutils и Python 3:

```bash
python3 -m unittest discover -s tests -v
bash -n vless-updater/update.sh
bash -n vless-updater/apply_candidate.sh
```
14 тестов проверяют билдер и helper на синтетических данных с заглушками
Xray/systemctl/runuser/curl. Реальные Xray, сеть, пользователь xray, весь retry-цикл,
конкурентный запуск и обработка сигналов этими тестами не проверяются.
При повторной проверке в среде ассистента 14 тестов прошли; это не CI на GitHub.
Секреты VPS, env, подписку, UUID и конфиги в тесты не переносить.

## Деплой и откат
Деплой и merge требуют отдельного согласования. Сначала проверить наличие
flock/runuser и настоящий xray run -test от пользователя сервиса. Остановить
таймер, исключить ручной запуск, сохранить старые скрипты и рабочий конфиг
с владельцем/режимом. Доставить build_xray_config.py, apply_candidate.sh и
update.sh вместе. Helper вызывается через bash, executable bit ему не нужен.
Не заменять работающий REALITY-конфиг без необходимости. После установки
вернуть таймер; запуск апдейтера и E2E-переключение согласовать отдельно.
При откате вернуть старые скрипты; конфиг восстанавливать только если менялся,
с исходными владельцем/правами и проверкой от пользователя сервиса перед restart.
Удаление бэкапов согласовывается отдельно. Merge сам не развёртывает код на VPS.

## Коммерческое использование
Новых Python-пакетов и сервисов нет. Xray-core использует MPL-2.0,
flock в util-linux имеет MIT-лицензию. n8n допускает внутренние деловые цели
по SUL; это не разрешение перепродавать доступ к n8n. Условия VPN-провайдера,
API, установленных сборок и иных компонентов отдельно не подтверждены.
